# RT52 — Compiled rule binding integrity

Aegis validates enabled tool-applicable regex caches at every public evaluation entry. The cache must exist, use only stateless `i,m,s,u` flags, and match the normalized declared pattern and flags. Equivalent flag ordering and JS source escaping are accepted; incidental stateless lastIndex is ignored and never modified. Invalid caches are skipped and produce an explicit `swarmlab.rt52.compiled-rule-requires-bound-stateless-matcher` ask floor that a severity mapping cannot weaken. Independent valid deny rules and predictor escalation remain effective. Disabled/non-applicable/nonregex rules are unchanged. Hosts should reload with loadPack after editing policy; Aegis does not automatically execute/recompile invalid cached policy, nor repeat load-time ReDoS admission.

The strict async wrapper delegates to the same entry validation and refuses invalid entry config without checkpoint I/O. During RT48 in-flight config drift, invalid critical matcher coverage can no longer safely be evaluated to recover a live deny; Aegis conservatively retains deny uncertainty for applicable critical coverage when critical maps to deny. Valid drift behavior remains unchanged. This conservatism is limited to a call already undergoing config-integrity refusal, not a change to the entry RT52 ask contract.

No public interface changed. Supported scope is ordinary loader-produced mutable CompiledRule data/RegExp caches, not arbitrary hostile JavaScript, proxies/getters/subclasses, process compromise or ReDoS redesign. Hosts own authenticated policy distribution and exact execution after return. Evidence is SwarmLab exp62, Spec68; traces and commits pinned in its claims ledger. No calibration or production incident claim.
